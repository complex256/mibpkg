# mibpkg — package manager for MIB2 High head units

Status: design approved in brainstorming 2026-09-26; spec awaiting review.
Backlog and deferred ideas: [docs/ideas.md](../../ideas.md).

## Goal

Let people who are not comfortable with a root shell install, update and remove custom
software on MIB2 High units (MHI2 / MHI2Q, QNX 6.5.0 armle), and let publishers ship updates
over time. The primary user has M.I.B. on an SD card and uses the green engineering menu
(GEM); ssh is a power-user convenience, not a requirement.

Success for v1: a user with M.I.B. can take an SD card holding a collection, bootstrap
mibpkg once, then install / update / remove / restart carmqtt entirely from a GEM screen,
survive reboots, and recover from a misbehaving package without ssh.

## Scope

**v1**
- M.I.B. bootstrap (Run Custom Script) that installs mibpkg and its single boot hook.
- Offline install / update / remove from collections on the SD card.
- In-car picker: GEM screens generated by mibpkg.
- Multiple collections (official + third-party) side by side.
- Boot drop-in folder `boot.d/` with a `phase` field (only `default` implemented).
- Service supervisor: restart policy, backoff, failed state, capped RAM logs, status.
- Package features: files, user config files, services, optional install/remove scripts.
- SHA-256 integrity check per package.
- `DISABLE` marker on the SD card as a no-ssh emergency stop.
- mibpkg updates itself as a package.
- carmqtt published as the first package, including migration of the existing hand install.
- Host-side tooling to build packages and generate a collection index.

**Not v1** (all tracked in docs/ideas.md)
- Online updates (v2, the next milestone).
- Signature verification (after v2; the index reserves a `signatures` field).
- Boot phases other than `default` (before navigation, after SIM data, ...).
- `[[patch]]` edits to stock files (json-merge etc.) — needed when carplay-rgi is packaged.
- Package payloads stored on the SD card; slim-bundle builder; hotspot web UI;
  package dependencies; automatic boot-loop detection; packaging tailscale / wireguard /
  carplay-rgi (other contributors involved).

## Platform constraints that shape the design

- Persistent storage cannot exec binaries. Everything runs from `/tmp`, which is RAM
  (`/dev/shmem`), cleared on boot, and **cannot hold subdirectories** — runtime files are flat
  `/tmp/mibpkg.*` names.
- `/mnt/app` and `/mnt/system` are mounted read-only; writes need `mount -uw` and must always be
  followed by `mount -ur`, on every exit path.
- `/bin/sh` is pdksh; shell pieces stay tiny and portable. All logic lives in the Rust binary.
- No stock drop-in boot directory exists. `startup.sh` (P5087) sources
  `/armle/scripts/{env,common}.sh`, but those are stock files sourced by many scripts, so they are
  not used as a hook.
- The SD card is mounted by the media system partway through boot and can be removed at any time.
- The unit is asleep when the car is off; power can drop without a clean shutdown.

## Architecture

One Rust binary, `mibpkg`, cross-built with `qnx65-armv7-toolchain` (the same toolchain as
carmqtt), plus two tiny shell shims:

| Piece | Role |
|---|---|
| `mibpkg` (Rust) | CLI (`install`, `remove`, `update`, `list`, `status`, `restart`, `rescan`, `bootstrap`, `gem`), supervisor (`supervise`), GEM screen generator. Also builds for macOS/Linux as host tooling (`mibpkg build`, `mibpkg index`). |
| `launch.sh` | Boot entry. Checks the `DISABLE` marker, copies `mibpkg` to `/tmp`, execs `mibpkg supervise`. |
| `gem.sh` | Target of every GEM button. Copies `mibpkg` to `/tmp` if needed, runs one action. |
| `custom.sh` (SD) | M.I.B. bootstrap: copies files in, runs `mibpkg bootstrap`. |

All filesystem paths go through one configurable root (default `/`), so the whole install
engine and supervisor run on the host against a temp directory in tests.

## On-car layout

```
/mnt/app/root/mibpkg/
  bin/mibpkg                 stored binary (never executed in place)
  bin/launch.sh, bin/gem.sh
  boot.d/<pkg>.<service>.toml  one file per service, written by mibpkg from manifests
  pkgs/<name>/<version>/     unpacked package files
  pkgs/<name>/current        text file naming the active version
  state/installed.json       installed packages, source collection, files placed outside pkgs/
  state/backups/             original copies of stock files mibpkg changed (kept once)
  state/config/<name>/       user-owned config files
  settings.toml              includes the package store path (pkgs/), so SD storage can be added later

/tmp (flat)
  mibpkg, mibpkg.pid, mibpkg.lock, mibpkg.status, mibpkg.log
  mibpkg.reload, mibpkg.restart.<id>, mibpkg.selfupdate, mibpkg.stop   request files polled by the supervisor
  mibpkg.<pkg>.<bin>         service binaries copied from pkgs/
  mibpkg.<svc>.log[.1]       service logs, ~256 KB cap, one rotation

SD card
  /mod/custom.sh (+ command.sh forwarder for older M.I.B.)   bootstrap
  /mibpkg/collections/<id>/index.json + packages/*.mpk
  /mibpkg/config/<pkg>/...    user-supplied config files
  /mibpkg/DISABLE             optional emergency stop
```

## Boot integration

`mibpkg bootstrap` inserts one line into `/mnt/system/etc/boot/startup.sh`, in
`start_late_drivers()` directly after `inetd > /dev/null 2>&1` (the place the existing
tailscale / mibwg / carmqtt hooks use):

```sh
    ## mibpkg supervisor. Best effort: detached, no stdio, never blocks boot.
    ( sleep 30; [ -x /mnt/app/root/mibpkg/bin/launch.sh ] && /mnt/app/root/mibpkg/bin/launch.sh ) </dev/null >/dev/null 2>&1 &
```

- Edited copy is validated with `ksh -n` on the unit before replacing the original; original kept
  as `startup.sh.pre-mibpkg`; replacement is stage-then-rename. Re-running bootstrap is idempotent.
- `mibpkg uninstall-self` removes the line and restores the backup if nothing else changed it.
- Packages never touch `startup.sh`; they get a `boot.d/` file.

`boot.d/<pkg>.<service>.toml` (service id = `<pkg>.<service>`):

```toml
package  = "carmqtt"
name     = "carmqtt"
exec     = "@pkg/bin/carmqtt"
args     = ["--config", "@config/carmqtt.toml"]
phase    = "default"
restart  = "always"          # always | on-failure | never
requires = ["@config/carmqtt.toml"]
```

Placeholders stay unresolved in `boot.d/`; the supervisor resolves `@pkg` through
`pkgs/<pkg>/current` each time it starts a service. That makes the `current` flip the single
commit point of an install: `boot.d/` files never name a version directory. An unknown `phase`
is reported as an error for that service and the service is not started (so future phases fail
safe on an old mibpkg).

## Supervisor

- `launch.sh`: if `/mibpkg/DISABLE` exists on any mounted SD/USB root, exit without starting
  anything. Otherwise copy `bin/mibpkg` → `/tmp/mibpkg` and `exec /tmp/mibpkg supervise`.
- `supervise` writes `/tmp/mibpkg.pid`, reads `boot.d/`, and for each `default`-phase service:
  copies `exec` to `/tmp/mibpkg.<pkg>.<bin>` (mode 755), starts it with stdout/stderr to its log,
  and monitors it.
- Restart policy with exponential backoff 1 s → 5 min. 5 exits within 10 minutes ⇒ state `failed`,
  no further restarts until an explicit `restart`.
- Log files capped at ~256 KB with one rotation (`.1`). Logs stay in RAM (flash wear).
- `/tmp/mibpkg.status` (JSON, written via temp + rename): per service state
  (`starting|running|backoff|failed|stopped|needs-config`), pid, restarts, last exit, since.
- Control is by request files in `/tmp`, polled every second (std-only: no `libc`/signal crate on
  the tier-3 QNX 6.5 target): `mibpkg.reload` ⇒ reread `boot.d/`, start new services, stop removed
  ones, restart changed ones and ones whose package `current` version changed;
  `mibpkg.restart.<id>` ⇒ restart one service; `mibpkg.selfupdate` ⇒ stop all, re-run `launch.sh`,
  exit; `mibpkg.stop` ⇒ stop all and exit. Stopping a service = `kill <pid>` (TERM), 5 s grace, then
  kill.
- On start the supervisor refuses to run if the pid in `/tmp/mibpkg.pid` is alive, and terminates
  any still-alive service pids recorded in a stale `/tmp/mibpkg.status` (orphans of a supervisor
  that died), so a restarted supervisor never runs duplicates.
- If the supervisor is not running when a CLI/GEM action needs it, the action starts it.
  Running services are not killed if the supervisor dies.
- A service whose required config is missing is not started and shows `needs-config`.

## Package format

`<name>-<version>.mpk` = gzip'd tar, unpacked by mibpkg itself (no reliance on the unit's tar/gzip),
containing `manifest.toml` and payload files. Paths in the archive must be relative and must not
escape the package directory (reject `..`, absolute paths, links).

```toml
[package]
name        = "carmqtt"          # [a-z0-9-]+
version     = "1.2.0"            # semver
description = "Car status to Home Assistant over MQTT"

[compat]                         # omitted = any unit
units    = ["MHI2Q"]             # unit identity: first line of /mnt/app/img_ver.txt contains
                                 # MMX2QC => MHI2Q, else MMX2 => MHI2 (verify on an MHI2);
                                 # settings.toml `unit = "..."` overrides detection

firmware = []                    # optional; each is a substring of the img_ver.txt first line

[[file]]
src  = "bin/carmqtt"             # destination defaults to the package version dir
mode = "755"

[[config]]
path     = "carmqtt.toml"        # lives in state/config/<pkg>/
example  = "carmqtt.toml.example"
required = true

[[service]]
name    = "carmqtt"
exec    = "@pkg/bin/carmqtt"
args    = ["--config", "@config/carmqtt.toml"]
phase   = "default"
restart = "always"

[scripts]                        # optional; each runs with a timeout; UI flags the package
post_install = "scripts/post-install.sh"
pre_remove   = "scripts/pre-remove.sh"
```

- `[[patch]]` is a reserved table name: v1 rejects packages that use it with a clear
  "requires newer mibpkg" message.
- Unknown top-level keys are rejected (so typos fail at build time on the host).
- Placeholders: `@pkg` (active version dir), `@config` (the package's config dir).
- v1 `[[file]]` destinations are limited to the package dir. Placing files in stock
  locations comes with `[[patch]]`.

### Config files

- Supplied by the user on the SD card at `/mibpkg/config/<pkg>/<path>`.
- On install/update/rescan, copied to `state/config/<pkg>/` if present on the card
  (card copy wins, previous internal copy kept as `.prev`).
- Never overwritten by package updates. Kept on remove; removed only with `remove --purge`.
- Missing required config ⇒ package installs, services show `needs-config`.

### Collections

A collection is a directory: `index.json` + `packages/`.

```json
{
  "format": 1,
  "collection": { "id": "complex256", "name": "complex256 packages" },
  "packages": [
    { "name": "carmqtt", "version": "1.2.0", "file": "packages/carmqtt-1.2.0.mpk",
      "sha256": "…", "size": 2412345, "description": "…",
      "compat": { "units": ["MHI2Q"] }, "uses_scripts": false }
  ],
  "signatures": []
}
```

- Generated by `mibpkg index <dir>` on the host from the `.mpk` files; never hand-written.
- `signatures` is reserved and ignored in v1.
- Every collection under `/mibpkg/collections/` on the card is read. A package is identified by
  `(collection id, name)`; installed packages remember their collection and only update from it.
  If two collections offer the same name, the GEM screen shows both with their collection id;
  installing one while the other is installed is refused (remove first).
- Collections the user has used are remembered in `state/installed.json` (id + name) for display.

## Install / update / remove

All actions take `/tmp/mibpkg.lock`; a second concurrent action exits immediately with
"busy". Sequence for install/update:

1. Read the collection index; check compat against the unit; pick the package.
2. Verify size and SHA-256 of the `.mpk` (streamed from the card).
3. Check free space on the package store (≥ 2 × unpacked size + margin).
4. `mount -uw /mnt/app` (abort cleanly if it fails).
5. Unpack into `pkgs/<name>/<version>.new/`, validate manifest, rename to `<version>/`.
6. Copy config files from the card if present.
7. Run `post_install` script if any (timeout; failure ⇒ delete the new version dir; imported
   config files are user data and stay).
8. Write `pkgs/<name>/current` (temp + rename) — the commit point.
9. Write `boot.d/` files for the package's services (version-independent, see Boot integration).
10. Update `state/installed.json` (temp + rename). Keep the previous version dir (one level of
    rollback); delete older ones.
11. `mount -ur /mnt/app` (always, including on error paths). Signal the supervisor.
12. Record the result (for `mibpkg.log` and the GEM "last result" line).

Any failure before step 8 deletes the new version dir and leaves the previous install
untouched. `rollback <pkg>` points `current` back at the kept previous version.

Remove: run `pre_remove`, delete `boot.d/` files, signal the supervisor to stop services, delete
`pkgs/<name>/`, update state; config kept unless `--purge`.

Backup/undo registry (`state/backups/`) is implemented in v1 and used by `bootstrap` for its own
`startup.sh` edit; `[[patch]]` reuses it later.

## In-car UI (GEM)

GEM screens are static `.esd` files in `/eso/hmi/engdefs/` (`screen <name> <parent>`, then
elements such as `script` buttons with a fixed command and `keyValue` rows). mibpkg generates
its own files (prefixed `mibpkg`, no clashes with stock or M.I.B. names):

- `mibpkg` (under the main engineering menu): SD collections summary, installed count,
  supervisor state, buttons *Rescan SD card*, *Update all (N)*.
- `mibpkg_<pkg>` per package: installed version, versions on the card (with collection id),
  service states, `⚠ runs scripts` if applicable, last result; buttons *Install* / *Update to X* /
  *Remove* / *Restart* / *Roll back* as they apply.

GEM `script` elements take a fixed command path, so every button points at a generated one-line
script in `/mnt/app/root/mibpkg/gem/` (e.g. `install-carmqtt-complex256.sh`) that runs
`gem.sh install carmqtt complex256` → `/tmp/mibpkg gem install carmqtt complex256`, which performs
the action and then regenerates all mibpkg screens (writing `/eso/hmi/engdefs` needs a transient
`/mnt/app` rw mount, done inside the same lock).

## Bootstrap and self-update

- SD card contains `/mod/custom.sh` (and `/mod/command.sh` forwarder for M.I.B. releases ≤ V3.7.1,
  the same pattern carplay-rgi uses). M.I.B. → Advanced Settings → Run Custom Script.
- `custom.sh` (pdksh-portable): copy `mibpkg`, `launch.sh`, `gem.sh` into
  `/mnt/app/root/mibpkg/bin/`, copy `mibpkg` to `/tmp`, run `/tmp/mibpkg bootstrap`, which adds the
  boot line, writes the GEM screens and starts the supervisor. Idempotent; re-running repairs.
- mibpkg is also a package (`mibpkg`) in the official collection. Updating it replaces
  `bin/*` (stage + rename) and restarts the supervisor from the new binary.

## carmqtt migration

- carmqtt gets a `manifest.toml` and is built as `carmqtt-<ver>.mpk`. Its `carmqtt.sh` wrapper's
  jobs (copy to /tmp, pid, log) move into the supervisor; the service runs the binary directly.
- One-time migration for the existing hand install, run by `mibpkg install carmqtt` when it
  detects `/mnt/app/root/carmqtt/`: import `carmqtt.toml` into `state/config/carmqtt/`, stop the
  old process, remove the old `startup.sh` hook line and its `##` comment in place (same
  `ksh -n`-validated edit path as mibpkg's own hook), and
  move the old directory to `/mnt/app/root/carmqtt.pre-mibpkg`.
- Behaviour to preserve: carmqtt relies on `Value::Lost` on disconnect and LWT; the supervisor's
  restart must not break its availability topic semantics (verify on the car).

## Error handling summary

| Situation | Behaviour |
|---|---|
| Corrupt/truncated `.mpk` | SHA-256/size mismatch ⇒ refuse, nothing written |
| Not enough space | refuse before mounting rw |
| rw remount fails | refuse, nothing written |
| Failure mid-install | new version dir deleted, previous version active |
| Power loss mid-install | `current` still names the old version; stale `*.new` dirs cleaned on next run |
| Double tap in GEM | lock ⇒ second action reports "busy" |
| Service crash loop | backoff, then `failed` until manual restart |
| Package breaks the unit | `DISABLE` on SD ⇒ launch.sh starts nothing |
| Unknown phase / `[[patch]]` | that service/package refused with "requires newer mibpkg" |
| `startup.sh` edit rejected by `ksh -n` | unit left untouched |

## Testing

- **Host unit/integration tests** (cargo, macOS/Linux) against a temp root: manifest and index
  parsing and validation, archive path safety, version comparison, compat matching, full
  install/update/rollback/remove including injected failures at each step, config handling,
  `startup.sh` hook add/remove (port carmqtt's `add_hook.py` cases to Rust), GEM `.esd` golden
  files, supervisor with fake services (crash, crash-loop, needs-config, SIGHUP reload).
- **Cross-build** via `qnx65-armv7-toolchain` (Rust image), as carmqtt's `scripts/build.sh`.
- **Real-unit checklist** (preferred over QEMU): M.I.B. bootstrap from SD, GEM screens appear,
  install carmqtt from SD incl. migration of the existing install, reboot survival, each GEM
  action, crash-loop → failed, `DISABLE` card, remove + purge, self-update.

## Verification items (resolve early in implementation, on the car)

1. `/mnt/app` free space (if tight, SD package storage moves into v1).
2. SD mount path(s) as seen from GEM scripts and from boot (`/fs/sda0`, `/fs/sdb0`, ...), and
   which slot M.I.B. requires.
3. QNX6 rename atomicity / power-loss behaviour on `/mnt/app`.
4. Unit identity values that distinguish MHI2 vs MHI2Q (`$SKUDIR/project`, `sku`, `rev`,
   `/mnt/app/img_ver.txt`) and the firmware version format.
5. GEM: are new `.esd` files picked up on GEM re-open or only after reboot; can a screen show
   output while a script runs; exact parent menu name for the entry; which user GEM scripts
   run as and whether they can `mount -uw`.
6. `launch.sh` timing: is the SD card mounted by the time the `DISABLE` check runs (if not,
   wait briefly for the media mount before deciding).
